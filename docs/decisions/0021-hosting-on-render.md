# 0021. Hosting on Render's free tier, described as a Blueprint

- **Status**: Accepted
- **Date**: 2026-09-24
- **Issue**: #54 (part of #5)

## Context

The final project must be testable by anyone at a public URL (or a recorded walkthrough), on this project's budget rule: no infrastructure cost. The system needs a Python API of ~260 MB resident, a Streamlit UI of ~70 MB, Postgres with pgvector, and Redis. The production session adds its own requirements: one-command, repeatable deploys; images, not commits; secrets only on the platform; a rollback that takes a minute; and knowing what the platform's limits cost in design.

## Options considered

| Option | Why not |
|---|---|
| **Hugging Face Spaces** (the first candidate: 16 GB of RAM for free) | Docker Spaces now require a paid plan, and a Space's outbound traffic is limited to ports 80, 443 and 8080, so a managed Postgres on 5432 is unreachable from it |
| A VPS (Hetzner or similar) | Not free, and it moves the firewall, TLS, backups and the host itself onto this project |
| Fly.io, Railway | No longer free for new accounts |
| **Render** | Chosen |

## Decision

**Render's free tier, described as code in `render.yaml`**: the API and the UI as two Docker web services built from the same image, Postgres 17 with pgvector and Key Value, all in Frankfurt, deployed from `main` on every push.

- **One account and one screen of secrets.** The owner types two provider keys once; the API key and the service token are generated by the platform and copied into the UI by the Blueprint. No secret lives in the repository, the image or the CI pipeline, which is what the production session asks: the pipeline holds nothing that could leak through a malicious workflow change.
- **Images per deploy and a one-minute rollback.** Render builds an image per commit and keeps previous deploys; rolling back redeploys one without rebuilding.
- **Graceful shutdown.** `maxShutdownDelaySeconds: 120` on the platform and `--timeout-graceful-shutdown 90` in uvicorn, so a deploy lets a review in flight finish instead of killing it and paying for it twice.
- **The database and the cache are private** (`ipAllowList: []`): reachable only from the private network.
- **EU region**, for the reasons in [ADR 0018](0018-data-privacy-and-providers.md).

## What the free tier costs in design, stated rather than hidden

- **The API is public.** Free web services cannot receive private network traffic, so the UI calls the API at its public address. The production session's topology keeps the AI service internal behind the one public door; here the door is the token, the key, the rate limit and the spend cap of [ADR 0020](0020-access-spend-and-probes.md), which is why that phase was built first. On a paid plan the API would move to the private network with no code change.
- **Cold starts.** Services sleep after 15 minutes idle and take up to a minute to wake. The UI waits up to 90 s with a message instead of reporting the API as down.
- **The free database is deleted after 30 days and not backed up.** The corpus is derived data, rebuilt from the BOE on every start of an empty database by the entrypoint: idempotent, non-fatal if the BOE is down, and free after the first run. What would be lost is the state only the service holds (paused agent runs, feedback), which is accepted for a demo and documented in [`docs/deployment.md`](../deployment.md).
- **One instance of each service.** A deploy has seconds of unavailability. Everything shared (cache, rate limit, spend counter) is already in Redis, so a second instance would not need code changes.

## Consequences

- Deploying is merging to `main`. The CI runs tests and a secret scan on the pull request; the platform builds and deploys after the merge. Evaluations do not run in this path ([#50](https://github.com/alexgraupera/AI4Devs-finalproject-AG/issues/50)).
- The configuration of the deployment is reviewed like code: a change of region, plan or variable is a diff to `render.yaml`.
- Moving off the free tier is a plan change in the Blueprint: the API to the private network, a paid database with point-in-time recovery, and the cold starts gone.
